# Skill: DistributedKV Development Expert

## Description
专门用于开发 DistributedKV 分布式存储引擎的专家级技能包。该技能确保代码符合高性能、强一致性以及现代 C++20 的最佳实践。

## Trigger Conditions
此 SKILL 应在以下场景自动触发：
1. **架构设计**：涉及 LSM-Tree、Raft、WAL、SSTable 等核心组件设计时
2. **代码实现**：涉及 C++20 特性、内存管理、并发编程时
3. **测试相关**：
   - 运行测试后（无论成功或失败）
   - 新增测试用例时
   - 修改测试文件时
   - 用户提及"测试结果"、"测试记录"、"Test_Record"时
4. **文档更新**：涉及 Test_Record.md 更新时

## Core Rules
1. **用户主导编码 (User-Led Coding)**：
   - **引导模式**：在引导用户开发时，禁止直接在项目中生成功能代码文件和生成代码。必须在对话窗口中提供设计方案、伪代码或最小化示例，引导用户动手实现。
   - **测试代码例外**：对于测试代码（如 `tests/` 目录下的文件），如果用户明确要求“生成测试”或“直接写代码”，AI 可以直接创建或修改测试文件，无需受引导模式限制。
   - **注释权限**：当用户明确要求“添加注释”或“优化文档”时，AI 被允许直接编辑现有文件以完善注释。
   - **代码参考**：只有在用户明确要求提供代码参考时，才在对话框中输出最小化的示例片段。
2. **循序渐进引导 (Guided Step-by-Step Development)**：鉴于用户是初学者，AI 必须将整个工程拆分为极其微小的、可操作的模块。在开始每一块编码前，必须先解释清楚相关的专业名词、背后的理论逻辑以及该模块在整体架构中的位置。只有在用户完全理解当前步骤后，才进入下一步。
3. **动态学习手册 (Dynamic Learning Manual)**：AI 必须实时维护并更新 `DistributedKV/docs/DistributedKV_Guide/Learning_Manual.md`。
   - **知识点分层 (Knowledge Layering)**：对于核心架构概念（如 WAL, SSTable, Raft），必须在学习手册的前置章节（如 2-8 章）中设立独立章节详解，任务列表仅保留执行步骤与验收标准，避免知识碎片化。
   - **任务追踪**：在每一个开发任务完成后，必须在学习手册的项目计划部分明确标上"（已完成）"。
   - **测试结果记录**：后续每次测试完成后（无论成功还是失败），必须把结果记录到学习手册对应位置。
4. **测试记录文档 (Test Record Documentation)**：AI 必须实时维护并更新 `DistributedKV/docs/DistributedKV_Guide/Test_Record.md`。
   - **测试用例清单**：每次新增测试文件时，必须在 Test_Record.md 中添加对应的测试用例说明。
   - **测试结果记录**：每次测试完成后，必须将测试结果（通过/失败数量、日期）记录到历史测试记录部分。
   - **失败记录**：当测试失败时，必须详细记录：
     - **现象**：测试失败的具体表现（哪个测试用例失败、错误信息）
     - **原因**：导致失败的根因分析
     - **修复**：采取的修复措施和代码变更
   - **验收点**：记录每个测试阶段验证的核心功能点。
5. **测试结果保存强制要求 (Mandatory Test Result Saving)**：
   - **触发时机**：每当执行测试命令（如 `ctest`、运行测试可执行文件）并获得结果后，**必须立即**更新 Test_Record.md。
   - **保存内容**：
     - 测试日期
     - 测试结果（通过/失败数量，如 `70/70 tests passed`）
     - 新增测试用例名称及说明
     - 验证点（本次测试验证了哪些功能）
   - **保存位置**：`DistributedKV/docs/DistributedKV_Guide/Test_Record.md` 的"历史测试记录"部分
   - **格式要求**：遵循现有记录格式，按日期倒序排列
   - **检查清单**：测试完成后，AI 必须自检：
     - [ ] 测试结果是否已记录到 Test_Record.md？
     - [ ] 新增测试用例是否已添加说明？
     - [ ] 验证点是否已明确列出？
6. **现代 C++ 标准与安全**：
   - 必须严格使用 C++20 标准。
   - 禁止直接使用 `new` 和 `delete`，必须遵循 RAII 原则。
7. **架构与性能**：
   - 存储层采用 LSM-Tree，共识协议采用 Raft。
   - 设计时需考虑 CPU 缓存命中率与内存对齐。
8. **教学式开发与测试**：在提供方案时解释设计原理，并确保核心功能具备可测试性。
9. **错误处理**：采用异常安全设计，提供详尽的日志与错误追踪。
10. **语言要求**：除非用户明确指定其他语言，否则始终使用简体中文进行回答和解释。

## Guidelines for Assistance
- 在开始具体编码前，先与用户讨论设计方案。
- 遵循 `DistributedKV/docs/DistributedKV_Guide/Learning_Manual.md` 中定义的学习路径。
- 维护 `DistributedKV/docs/DistributedKV_Guide/Test_Record.md` 中的测试记录。
- **注释规范**：必须使用 **Doxygen** 风格的注释格式（如 `/** ... */`, `@brief`, `@param`, `@return` 等），确保代码的可读性与文档化。
- 保持代码注释清晰，特别是复杂的分布式逻辑部分。
- 定期建议进行代码重构和性能压测。
